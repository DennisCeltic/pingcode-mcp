# PingCode MCP 洞察类功能设计

## 目标

把 MCP 从基础 API 助手升级为研发管理场景助手，优先覆盖 PM、研发、TL 高频使用的只读洞察能力：

- PM：项目健康度、周会风险、汇报素材。
- 研发：接手工作项前快速理解上下文。
- TL：团队负载、交付风险、站会前巡检。

本轮先实现只读工具，降低误操作风险。批量变更、会议纪要转任务、Git/PR 联动作为后续阶段。

## 已实现工具

### `pingcode__project_health_report`

生成项目或迭代健康度报告。

核心输入：

- `project_id`：限定项目范围。
- `sprint_id`：限定迭代范围。
- `assignee_ids`、`state_ids`、`type_ids`：进一步筛选。
- `stale_days`：多少天未更新视为停滞，默认 7。
- `due_soon_days`：多少天内到期视为临期，默认 7。
- `max_items`：最大扫描工作项数量，默认 500，最多 2000。

输出内容：

- 健康度：绿色、黄色、红色。
- 关键指标：逾期、临期、无负责人、停滞、疑似阻塞。
- 状态分布。
- 负责人负载 Top 10。
- 高优先级关注项。
- 建议动作。

### `pingcode__work_item_context`

汇总单个工作项上下文，帮助研发/TL/PM 快速接手。

核心输入：

- `work_item_id`：工作项 ID。
- `activity_limit`：最近活动条数，默认 5。
- `comment_limit`：最近评论条数，默认 5。
- `include_attachments`：是否读取附件列表，默认 true。

输出内容：

- 基本信息：项目、类型、状态、优先级、负责人、迭代、计划时间、工时。
- 描述摘要。
- 父级工作项。
- 最近活动。
- 最近评论。
- 附件列表。
- AI 接手提示：无负责人、逾期、停滞、阻塞等。

### `pingcode__team_load_report`

按负责人生成团队负载报告。

核心输入：

- 支持与 `project_health_report` 相同的范围筛选。
- `start_at` / `end_at`：如果同时传入，会尝试汇总每个负责人的登记工时。

输出内容：

- 成员维度的活跃项、逾期、临期、停滞。
- 预估工时、剩余工时。
- 可选的已登记工时。
- 负载倾斜和风险负责人提示。

### `pingcode__risk_scan`

生成可行动的交付风险清单。

风险规则：

- 高：逾期未完成、疑似阻塞。
- 中：无负责人、临期。
- 低：长时间未更新。

输出内容：

- 风险等级、类型、工作项、负责人、原因。
- 建议处理顺序。

## 设计取舍

- 只读优先：本轮不做自动批量更新，避免误改状态、负责人或迭代。
- 容错优先：评论、附件、活动 API 失败时局部降级，不让整个报告失败。
- 字段兼容：PingCode 返回字段可能因项目类型不同而不同，状态、负责人、优先级、时间字段均按可选字段解析。
- 默认限制扫描量：默认最多 500 个工作项，避免大企业空间下 API 调用过重。

## 后续建议

1. 范围化周报升级：把 `weekly_report` 改造成支持 `project_id`、`sprint_id`、`assignee_ids`、自定义时间段。
2. 会议纪要转任务：从会议纪要提炼 action item，先预览，再创建工作项。
3. 批量变更预览：批量移迭代、改负责人、改状态前输出 diff 和风险提示。
4. Git/PR/CI 联动：根据分支名、commit、PR 标题识别工作项编号，同步评论和交付状态。
5. 质量洞察：Bug 趋势、返工率、需求变更频率、测试阻塞项。
